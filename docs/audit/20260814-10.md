# 路线对齐审计 · 2026-08-14 · 第 10 轮

## 本轮目标

#16 URL 摄取 + SSRF 防护（审计 F-10：防护与能力同批交付）

## 实际完成

- **SSRF 防护模块**（core/security/ssrf.py）五层防线：协议白名单 / 域名白名单（含子域匹配与后缀陷阱防护）/ 解析后全地址 IP 校验（含 IPv4-mapped IPv6 解包，防 DNS rebinding）/ 重定向逐跳重校验（上限 3 跳）/ 流式响应体大小上限
- **URL 摄取端点**：POST /api/v1/kb/{id}/documents/url（202 + JobOut），HTML→文本提取（script/style 剥离）、异步任务链入队、source.html 落工作目录
- **任务队列接线**：celery broker 从 Settings 读取（ADR-002）；backend=None（状态在 ingest_jobs 表，无需结果后端）；worker 入口 scripts/worker.py
- **测试 27 例**：IP 判定矩阵 15 例（内网/环回/元数据/ULA/映射 IPv6）、协议与白名单、假网站抓取集成（标题/正文/重定向/大小上限）、API 级 SSRF 拦截与端点全链路（eager 管线）
- .html/.htm 入支持格式

## 本轮修复的真实缺陷

1. celery 无 filesystem **结果后端**（filesystem 仅是 broker 传输）——backend 必须为 None
2. kombu filesystem 传输不需 pyfilesystem（误加 fs 依赖已移除；fs 2.4 自身依赖已删除的 pkg_resources）
3. 链式任务 .s() 返回值串参——统一 .si() 不可变签名
4. 测试 Qdrant 双客户端目录锁——复用应用自有服务构建管线
