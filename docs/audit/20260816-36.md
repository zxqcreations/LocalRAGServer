# 路线对齐审计 · 2026-08-16 · 第 36 轮（BM25 倒排索引重构，v1.1 余项）

## 本轮完成

**稀疏侧检索结构优化**（SLO 分解中 84.6ms 的最大单项）：

- `core/retrieval/bm25.py` 全语料扫描 → **倒排索引（posting lists）**：
  - 查询只触碰含查询词的文档（posting list 交集累积），不再逐文档逐 token 扫描
  - posting 以 `array('i')`（doc_id）+ `array('h')`（tf）紧凑存储；构建期瞬态
    用 list 对（doc_id 复用同一 int 对象、freq 多为驻留小整数），构建完成后
    释放 token 列表——稳态内存较旧实现（永久保留全部 token 列表）大幅下降
  - 每文档长度归一化常量构建期预计算，查询内层循环压缩（range 索引 + 局部变量）
  - tokenizer 单遍正则（`拉丁词|[CJK单字符]` 交替），替代「全词扫描 + 逐字符
    正则」双遍
  - 排序确定化：`(-score, doc_id)`——与旧实现稳定排序的同分语义一致
- 评分公式逐项同序（浮点位级一致），求和顺序不同（按查询词 vs 按文档）
- 黄金对拍测试：tests/test_bm25.py 新增参考实现（旧全扫描算法）逐查询对拍
  + 同分确定性测试

## 实测（10k 文档 × 512 字符 chunk，5k 词表，中英混合）

| 指标 | 旧实现 | 新实现 |
|---|---|---|
| 索引构建 | 3.60s | 3.05s |
| CJK 查询（3-4 字符词） | 143-164ms | 25-36ms（3.9-6.0×） |
| 英文查询 | 130ms | 0.01ms（~10⁴×） |
| 结果一致性 | — | 位级一致（1e-12） |

SLO 影响：稀疏侧从 84.6ms 降至 0-36ms（随查询语言），P95 预算内腾出 ~50-85ms。
