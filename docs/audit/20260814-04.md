# 路线对齐审计 · 2026-08-14 · 第 04 轮

## 本轮目标

P0-6 安全最小骨架：Bearer 认证 + fail-closed + 上传防护 + 错误码目录

## 实际完成

- **最小认证骨架**（审计 F-01 落地）：
  - Bearer API Key 中间件随第一批接口同批交付；`secrets.compare_digest` 常数时间比较
  - 未配置 Key → **fail-closed**（业务接口全部 503 auth_unconfigured，仅 /health 开放）
  - host 非回环地址时启动打印安全警告
- **上传防护**（审计 F-07/F-09 落地）：
  - 扩展名白名单 + **MIME 魔数校验**（不信任客户端声明的扩展名，如 fake.pdf 被拒）
  - 上传大小上限（可配置 max_upload_mb）+ PDF 页数上限（max_pdf_pages，TooManyPagesError）
  - 文件名 basename 规范化（防路径穿越）
- **错误码目录初版**（审计 ARC-010/F-19 落地）：apps/api/errors.py 定义 12 个语义化错误码（auth_required/auth_invalid/auth_unconfigured/kb_not_found/doc_not_found/unsupported_format/invalid_file_content/payload_too_large/empty_document/too_many_pages/validation_error/internal_error），全局异常处理器统一转信封，error 字段不泄露堆栈/内部路径
- **测试**：test_auth.py 5 例（fail-closed/缺失/无效/有效/健康开放）+ 上传魔数测试；共享 client/auth_headers fixture 提升至 conftest
