# 路线对齐审计 · 2026-08-16 · 第 35 轮（CI CVE 门禁修复 + 两公告登记）

## 背景

第 34 轮提交（8434544）CI 失败，且此前 docs-only 提交（9031a26）同样失败——
两处均为 M-11「pip 直管依赖 CVE 监控」步骤问题，与第 34 轮代码无关：

1. **Windows runner**：pip-audit 的 requirements 解析器以平台 locale 编码
   （cp1252）打开 requirements-security.txt，文件内中文注释触发
   `UnicodeDecodeError` 崩溃
2. **双 runner**：ragas 依赖树出现两条新公告，且**上游均无修复版本**

## 公告评估与处置

| 公告 | 内容 | 评估 | 处置 |
|---|---|---|---|
| PYSEC-2026-3046（CVE-2026-6587，ragas） | Multi-Modal Faithfulness 模块 SSRF | 本项目 RAGAS 评测仅文本模式 + 本机评判模型，多模态模块从不调用；受影响版本覆盖至 0.4.3（当前最新），**无修复版本可升** | 登记不修（沿用 L-8 先例） |
| PYSEC-2026-2447（CVE-2025-69872，diskcache） | 缓存 pickle 反序列化 | 本地向量（AV:L，需缓存目录写权限）；经 ragas→diskcache 传递引入，本项目不直接使用；评测离线运行、无不受信输入；**无修复版本可升** | 登记不修 |

处置方式：CI M-11 步骤对两 ID 显式 `--ignore-vuln`（理由写入
requirements-security.txt 头注与本文档），**其余新公告仍照常使门禁失败**——
监控能力不降级，已知风险有账可查。

## 修复

- requirements-security.txt 改为纯 ASCII（注释英文化；附头注说明编码约束
  ——中文注释是 Windows 解析器崩溃根因）
- ci.yml M-11 步骤加 `--ignore-vuln` 两行 + 注释指向理由文档
- 本地复验：`pip-audit -r requirements-security.txt --ignore-vuln …`
  →「No known vulnerabilities found, 2 ignored」；smoke.py 全链路通过
  （CI 中该步因前置失败被跳过，本地补跑）
